# MC Panel state machines

For a queued action, track the returned job ID. A successful HTTP request means the panel accepted the work. Only a job in `Completed` confirms completion. For the controls available *now*, read the server again. For example, a server can return to `Running` while its backup job is still compressing files.

## Jobs and server controls

| Current job state | Event and guard | Result |
| --- | --- | --- |
| Queued | Worker claims an uncanceled row | Running |
| Queued | Administrator cancels before claim | Canceled. A new server awaiting this install moves from Installing to Error. |
| Queued | Handoff fails | Failed |
| Running | Work returns successfully | Completed |
| Running | Work throws | Failed |
| Running | An eligible cancellation is requested | Running with cancellation requested until the worker reaches a safe boundary. An operation that already committed can complete. |
| Queued or Running | Startup finds unfinished work | Interrupted |
| Failed, Interrupted or Canceled | Supported retry with saved input and eligible server | New queued job with `retryOf`. An existing active retry is returned. |

An immediate stop creates its own running job and supersedes queued lifecycle work. It can also cancel an in-flight start or restart. Normal cancellation uses the API's `canCancel` field. Check `canRetry` before offering retry, then handle a conflict if the server changed. Terminal jobs stop individual job polls. The Activity list may continue refreshing to discover new jobs. Rollback to older panel versions has a separate compatibility conversion for historical job states.

The worker claims and terminal updates are conditional SQL writes. Keep decisions that race with workers in the database. See [job rules](src/McPanel.Api/Services/JobLifecycle.cs), [worker and cancellation](src/McPanel.Api/Services/OperationQueue.cs), [retry dispatch](src/McPanel.Api/Services/JobRecoveryService.cs) and [browser consumption](src/McPanel.Web/src/lib/job-lifecycle.ts).

| Server workflow | Transitions and observations |
| --- | --- |
| Installation | Installing → Stopped after activation. Failure, startup interruption or cancel-before-claim leads to Error. Official install retry checks the destination and saved input. |
| Process control | Stopped or Crashed → Starting → Running on readiness. A stop can supersede readiness. A requested stop goes through Stopping to Stopped. The runtime also recognizes a clean exit. Unexpected failure goes to Crashed. |
| Crash recovery | Crash → delayed attempt → start or another crash. Three attempts use delays of 5, 15 and 60 seconds. Explicit stop or disabled recovery cancels pending work. The owning supervisor rechecks the current attempt before starting. |
| Backup | A consistent Running or Stopped server enters BackingUp for the snapshot. Saves resume and the snapshot phase ends before compression, verification and publication finish. |
| Update or software change | A stopped Minecraft server enters Updating. Successful activation restores Stopped. Gate can update a running proxy and restart it. Failure handling uses the previous installation and the observed process. |
| Reconciliation and repair | The persistent runtime supplies process observations. Regular reconciliation preserves an in-progress backup or update when the process is running, stopped, or absent. A reported crash still takes precedence. A recovery-required record carries a reason and blocks changes. Successful journal repair clears the flag. |
| Restart required | Changes to live configuration can set this flag alongside Running. A successful launch clears it. |
| Editing | Files, icons, properties, mod installation and player-list actions check that the process agrees with Running, Stopped or Crashed. Inventory writes and backups have narrower eligibility. Restore requires a stopped server. |
| Browser request | Idle → submitting → awaiting observation if HTTP finishes first, or awaiting response if the observed state changes first. A matching error or display timeout releases the pending label. The request belongs to its server ID. |

## Durable operations and ownership

| Workflow | Authority and transitions |
| --- | --- |
| Software activation | The transaction moves from prepared to activating to commit recorded to committed. An uncommitted journal describes how to restore original files and metadata. Cleanup follows the durable commit marker. [Activation transaction](src/McPanel.Api/Services/SoftwareActivationService.cs) |
| Backup restore | Staged → activated → commit recorded → committed, or activated → files restored → rolled back. Restart opens the existing journal and uses its commit marker to choose finalization or rollback. Failed repair preserves the journal and records a recovery reason. [Restore transaction](src/McPanel.Api/Services/BackupService.cs) |
| Filesystem import | A validated, staged copy gains a journal, moves to the destination, then commits the database transaction. On restart, the database row and destination together determine whether to finalize, undo an uncommitted move, or request repair. [Import activation](src/McPanel.Api/Services/ServerImportService.cs) |
| JAR and modpack input | Upload or prepare → inspectable token → exclusively claimed staging directory → consumed and released. Unclaimed inputs expire. A custom JAR claim can be returned on precommit failure. The directory move is the cross-request claim. [Custom JARs](src/McPanel.Api/Services/CustomJarService.cs) and [modpacks](src/McPanel.Api/Services/ModpackService.cs) |
| Mod and plugin install | Select version and dependencies → queue → stage and verify files → commit or unwind changes. The installer uses the server lock. A modpack baseline separately classifies later file drift as added, modified or removed. [Extension installer](src/McPanel.Api/Services/ModrinthModInstallerService.cs) and [baseline](src/McPanel.Api/Services/ModpackService.cs) |
| Save suspension | Acquire → persist token and deadline → flush confirmed → renew or release. An expired lease invalidates the snapshot. Resume requires confirmation and failures remain eligible for maintenance retry. [Runtime lease](src/McPanel.Api/Services/RuntimeReliability.cs) |
| Backup retention | A verified capture enters retention. Pin and unpin change eligibility. Retention protects the newest verified copy present on disk. [Retention](src/McPanel.Api/Services/BackupRetention.cs) |
| Recovery points | Stage and checksum → publish locally → optionally replicate and verify. An error after local publication is recorded on the recovery point. The local copy can still be downloaded. [Recovery bundles](src/McPanel.Api/Services/RecoveryBundleService.cs) |
| Instance export and import | Export locks the selected instances, packages state, then makes the artifact available through the completed job. Import stages payloads and tracks moved paths until the database commits. Imported instances start offline. [Instance archives](src/McPanel.Api/Services/InstanceExportService.cs) and [single-server exports](src/McPanel.Api/Services/ServerExportService.cs) |
| Gate configuration | Edit or backend change → dirty revision → applied, or dirty with a recorded apply error → retry. Secret generation, reveal and replacement have separate confirmation and visibility states. Gate release update stages a verified binary and retains the previous version for rollback. [Gate service](src/McPanel.Api/Services/GateProxyService.cs) |
| Schedule and run history | Disabled ↔ waiting. A due or manually queued schedule can be claimed once. A running one-shot disables future execution immediately. Completion or failure closes its history row. On restart an open history row becomes interrupted. One overdue backup-only schedule run may be replayed. [Scheduler](src/McPanel.Api/Services/SchedulerService.cs) |
| Incident and delivery | Open → resolved. An open incident may get an opening notification. A resolved incident is eligible for recovery notification only after its opening was delivered. Successful delivery writes the timestamp. A new occurrence creates a new incident. [Monitor](src/McPanel.Api/Services/OperationsMonitor.cs) |
| Player presence and inventory | Join, leave and server exit change observed presence. Whitelist, operator and ban membership change independently. Inventory restore checks offline status and file revision, saves a safety copy and atomically writes the replacement. [Players](src/McPanel.Api/Services/PlayerService.cs) and [inventory](src/McPanel.Api/Services/PlayerInventoryService.cs) |
| Runtime upgrade | Serving → waiting for idle on explicit request → draining when no workloads are active. A changed executable can also initiate draining. The lifecycle gate orders new launches against drain admission. [Runtime socket service](src/McPanel.Api/Services/PersistentRuntime.cs) |
| Deployment | Stage and validate → preserve previous installation → activate → probe readiness. Failure enters compatibility-checked rollback. An active workload can defer runtime replacement. [Installer and updater](mcpanel.sh) |
| Administrator and session | First run issues a setup token. Committing the administrator consumes setup. Login establishes a cookie for the current stamp. Logout or password change rotates the stamp and revokes the old hub audience. [Authentication](src/McPanel.Api/Services/AdminAuthService.cs) and [audience](src/McPanel.Api/Services/SessionAudience.cs) |
| Database schema | Startup inspects the recorded version and schema shape, snapshots an existing database before migration, applies pending SQL in a transaction, then records the version. Incompatible state fails the preflight. [Schema migration](src/McPanel.Api/Data/SchemaMigration.cs) |
| Distribution catalog and downloads | An empty or expired catalog acquires the refresh lock and rechecks freshness. Downloads resolve an allowed source, stream bounded data, check integrity and release partial output on failure. [Catalog and download service](src/McPanel.Api/Services/DistributionCatalogService.cs) |
| Java discovery | Candidate → probe → registered or skipped. Rescan removes stale automatically discovered entries and retains explicitly registered runtimes. Launch probes the selected runtime again. [Java discovery](src/McPanel.Api/Services/JavaDiscoveryService.cs) |
| Console persistence and readiness | Runtime output enters a bounded queue, then reaches durable history or increments the drop count. A waiter registers before checking history, resolves once on a matching line or deadline and unregisters. The panel relays durable lines using a saved sequence. [Runtime logging](src/McPanel.Api/Services/RuntimeReliability.cs) and [console waiters](src/McPanel.Api/Services/ConsoleService.cs) |
| Resource ownership | Server locks serialize conflicting operations. Disk and memory reservations move from held to released on cleanup or process exit. Workload admission and final release happen under their respective locks. [Archive reservations](src/McPanel.Api/Infrastructure/ArchiveIO.cs) and [runtime admission](src/McPanel.Api/Services/RuntimeReliability.cs) |

## Browser interaction and parsing

| Surface | States, events and owner |
| --- | --- |
| Application entry | Loading → setup, login, authenticated or unavailable. Retry repeats the query. A failed background refresh can keep the last authenticated view. Expiry clears private query data. [Application routes](src/McPanel.Web/src/App.tsx) |
| Create server | Regular follows type → version → runtime → confirm. Proxy follows type → Gate details. Back follows the selected path. Submission leads to a job route, which opens the server on completion or shows its terminal outcome. [Creation paths](src/McPanel.Web/src/pages/core-pages.tsx) |
| Software and catalog | Official, existing-JAR and upload choices determine required input. Upload uses idle, pending, success and error mutation states. Review → submit → observe job. A successful consuming job invalidates that token. Catalog search and selection lead to version choice and job tracking. [Software](src/McPanel.Web/src/pages/software-page.tsx), [uploads](src/McPanel.Web/src/hooks/use-custom-jar-upload.ts), [catalog](src/McPanel.Web/src/components/modrinth-browser.tsx) and [pack selection](src/McPanel.Web/src/components/modpack-picker.tsx) |
| Console | Connect → catch up → live. Disconnect → reconnect → catch up again. Buffers drain in sequence. Only the current connection generation can finish catch-up. Revocation or disposal closes the session. [Console](src/McPanel.Web/src/pages/operations-pages.tsx) |
| Files and preview | Browsing → opening → editing, or choose preview, create/move, delete or replace. Navigation supersedes pending reads and their errors. Edits made during a save stay open. The next save verifies the stored text and revision before writing again. An image request moves from loading to ready or failed, with object URL cleanup on exit. [Files](src/McPanel.Web/src/pages/operations-pages.tsx) and [preview](src/McPanel.Web/src/components/file-image-preview.tsx) |
| Drafts | Baseline → dirty → saving → saved or error. A properties revision conflict can load current values and rebase local changes. Dirty navigation can be blocked, canceled or resumed after discard. [Properties](src/McPanel.Web/src/pages/core-pages.tsx) and [navigation guard](src/McPanel.Web/src/hooks/use-unsaved-changes.tsx) |
| Settings and schedules | Open editor → change fields → submit → close on success or keep draft on error. Schedule editing, deletion and history have exclusive dialog states. Gate backend source, route editor and default-backend choice determine the configuration revision being saved. [Schedules](src/McPanel.Web/src/pages/management-pages.tsx) and [Gate backends](src/McPanel.Web/src/pages/gate-backends-page.tsx) |
| Images, sheets and dialogs | The icon picker decodes, accepts an exact-size PNG or opens a crop, then closes and releases its URL after exit. Selected mod, player and inventory views retain content during dismissal. Confirmation actions run before close. [Icons](src/McPanel.Web/src/components/server-icon.tsx), [selection](src/McPanel.Web/src/pages/mods-page.tsx), [inventory sheet](src/McPanel.Web/src/components/player-inventory-sheet.tsx) and [dialogs](src/McPanel.Web/src/components/modal.tsx) |
| Shared views | Query and mutation status drive loading, retained data, error, retry and success. Routes, tabs and pagination own selection. Theme preference is light, dark or system, with resolved appearance following preference or the OS. [Feedback](src/McPanel.Web/src/components/feedback.tsx) and [theme](src/McPanel.Web/src/components/theme-provider.tsx) |
| Text interpreters | The JVM tokenizer tracks unquoted, single-quoted, double-quoted and escaped input. Terminal sanitization tracks text, escape introducers, CSI and terminated control strings. MOTD formatting accumulates style until color or reset, or inherits style through JSON components. [JVM arguments](src/McPanel.Api/Infrastructure/JvmArgumentParser.cs), [terminal text](src/McPanel.Web/src/lib/terminal-sanitize.ts) and [MOTD](src/McPanel.Web/src/lib/motd.ts) |
| Request identity | A new creation intent gets a client request ID. A software-change retry retains its ID until the intent changes or the request succeeds. The API checks existing jobs for reuse. [Request IDs](src/McPanel.Web/src/lib/client-request-id.ts) and [software submission](src/McPanel.Web/src/pages/software-page.tsx) |
| Antiforgery | A write obtains a token on demand, then reuses it. Session changes or a rejected token invalidate the cached value. A private request receiving 401 also triggers session expiry. [API client](src/McPanel.Web/src/lib/api.ts) |

## Changing a transition

Start with the row for the owning workflow. Distinguish requested work, the worker's result and the observed process. Preserve enum values, DTO fields, revision checks, and on-disk commit markers when updating a transition. Exercise the competing event as well as the normal path. [Queue and cancellation tests](tests/McPanel.Api.Tests/OperationQueueTests.cs), [stop races](tests/McPanel.Api.Tests/ImmediateStopRaceTests.cs), [journal recovery](tests/McPanel.Api.Tests/SoftwareActivationServiceTests.cs), [server control matrix](src/McPanel.Web/src/pages/server-overview.test.tsx) and [console reconnect tests](src/McPanel.Web/src/pages/console-page.test.tsx) cover these boundaries.
